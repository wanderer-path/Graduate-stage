
# 科研论文常见英文术语

> **适用范围**：以计算机科学、人工智能、机器学习论文为主要语境，兼顾一般科研论文。  
> **使用方式**：读论文时按类别查询；写论文时重点关注术语的准确含义和“常见误区”。  
> **说明**：同一术语在不同学科、会议或具体论文中可能有细微差异，应以作者给出的定义为准。

## 1. 研究定位与论文结构

| 英文术语 | 常见中文 | 核心含义 / 阅读提示 |
|---|---|---|
| Paper / Manuscript | 论文 / 稿件 | **Paper** 泛指论文；**manuscript** 常指准备或正在投稿的稿件。 |
| Abstract | 摘要 | 简述问题、方法、结果与贡献，不等于引言。 |
| Introduction | 引言 | 说明研究背景、问题价值、现有不足和本文贡献。 |
| Related Work | 相关工作 | 介绍并比较已有研究，通常用于定位本文与既有工作的关系。 |
| Literature Review / Survey | 文献综述 / 综述 | 系统梳理领域研究；**survey paper** 通常以综述本身为主要贡献。 |
| Background / Preliminaries | 背景 / 预备知识 | 解释必要概念、符号、理论或已有技术。 |
| Method / Methodology | 方法 / 方法论 | **Method** 常指具体做法；**methodology** 更偏向方法体系或研究设计，但论文标题中也常宽泛使用。 |
| Experiments | 实验 | 介绍实验设置、数据、对比方法和结果。 |
| Results | 结果 | 报告观测到的数据、数值或现象。 |
| Discussion | 讨论 | 解释结果的意义、原因、适用范围及局限性。 |
| Conclusion | 结论 | 总结核心发现与贡献，通常不应引入未经展示的新结果。 |
| Appendix / Supplementary Material | 附录 / 补充材料 | 放置推导、额外实验、实现细节等。 |
| Research Question (RQ) | 研究问题 | 论文试图回答的具体问题。 |
| Problem Formulation | 问题形式化 | 用数学符号或正式定义表述研究问题、变量和约束。 |
| Motivation | 研究动机 | 为什么要研究这个问题，以及现有方法为何不足。 |
| Contribution | 研究贡献 | 本文实际新增的知识、方法、数据、理论或实证发现。 |
| Novelty | 新颖性 | 与已有研究相比的新内容；“新”并不自动意味着“有效”或“重要”。 |
| Assumption | 假设条件 | 分析或方法成立时预先接受的条件，如数据独立同分布。 |
| Hypothesis | 待检验假设 | 可以通过实验或理论检验的具体命题。 |
| Scope | 研究范围 | 明确研究覆盖哪些情况，以及哪些不在讨论之内。 |
| Notation | 符号约定 | 对变量、集合、索引等记号作出统一说明。 |

## 2. 基准、对比与创新性

| 英文术语                        | 常见中文        | 核心含义 / 阅读提示                               |
| --------------------------- | ----------- | ----------------------------------------- |
| **Benchmark**               | 基准测试 / 评测基准 | 用于统一比较方法的一套任务、数据、指标与评测规则；语境中也可能简指某个基准数据集。 |
| **Baseline**                | 基线方法 / 对照方法 | 用作比较参照的已有方法或简单策略。需检查是否在公平条件下实现和调参。        |
| **SOTA (State of the Art)** | 当前最先进水平     | 在**明确任务、数据、指标和评测条件**下达到当前领先水平；不是对所有场景都最优。 |
| State-of-the-art Method     | 先进方法        | 在相关任务上具有领先表现的方法；不一定在每个数据集上都排名第一。          |
| Leaderboard                 | 排行榜         | 汇总某评测任务上各方法结果的排名页面或表格。                    |
| Comparative Study           | 对比研究        | 系统比较多个方法的效果、成本或适用条件。                      |
| Comparison / Comparator     | 比较 / 对照对象   | 对照的行为或所选对照方法，需明确比较维度。                     |
| Ablation Study              | 消融实验        | 移除或替换部分组件，以检验该部分的实际作用。                    |
| Variant                     | 变体          | 在原始方法上改变某个结构或设置后形成的版本。                    |
| Control Group               | 对照组         | 用于检验处理、因素或干预效果的参照组；实验科学中尤常见。              |
| Fair Comparison             | 公平比较        | 统一或合理控制数据、计算预算、评价流程等条件。                   |
| Evaluation Protocol         | 评测协议        | 规定如何划分数据、运行模型、计算指标和聚合结果。                  |
| Upper Bound / Lower Bound   | 上界 / 下界     | 理论或实验上的界限；必须说明界限约束的量与成立条件。                |
| Oracle                      | 理想化参考方法     | 使用现实部署中可能不可获得的信息的参考方法，常用于估计性能上限。          |
| Trade-off                   | 权衡          | 某一目标改善时，另一目标可能变差，如准确率与延迟的权衡。              |
| Competitive                 | 有竞争力的       | 与已有强方法表现接近或具备某方面优势；不等于必然第一。               |
| Outperform / Surpass        | 优于 / 超过     | 指定指标上的表现更好，需确认指标方向（越大/越小越好）。              |
| Improvement / Gain          | 提升 / 增益     | 相对于某参考方法的变化，需要区分绝对差值与相对变化。                |
| Performance Gap             | 性能差距        | 两种方法或不同场景下的性能差异。                          |
| Downstream Task             | 下游任务        | 使用已有特征、预训练模型或中间表示来解决的具体应用任务。              |

**例子：** 在固定数据划分和 Accuracy 评测协议下，以模型 A 为 **baseline**，在某个 **benchmark** 上比较新模型 B；若 B 达到了该评测体系当前公开的最佳结果，可以说 B 在这个特定设置下实现了 **SOTA**。

## 3. 数据集与实验设计

| 英文术语 | 常见中文 | 核心含义 / 阅读提示 |
|---|---|---|
| Dataset | 数据集 | 用于训练、验证或测试的一组样本。 |
| Sample / Instance | 样本 / 实例 | 数据集中的一个观测对象。 |
| Feature | 特征 | 描述样本的信息或经过处理得到的变量。 |
| Label / Target | 标签 / 目标值 | 监督学习中模型需要预测的结果。 |
| Annotation | 标注 | 人工或自动为数据添加标签、边界框或其他说明。 |
| Training Set | 训练集 | 用于拟合模型参数的数据。 |
| Validation Set | 验证集 | 用于选择模型、调超参数或早停的数据。 |
| Test Set | 测试集 | 用于对最终选定的方法进行独立评估；不应反复用于调参。 |
| Data Split | 数据划分 | 将数据分成训练、验证和测试等互不重叠的部分。 |
| Held-out Data | 留出数据 | 未参与某阶段拟合的数据；需看具体是验证集还是测试集。 |
| IID / i.i.d. | 独立同分布 | 样本之间独立且来自同一概率分布的理想化假设。 |
| Non-IID | 非独立同分布 | 数据不满足 IID；可能是分布不同、样本相关或两者兼有。 |
| In-Distribution (ID) | 分布内 | 与模型训练时假设或覆盖的数据分布一致或接近。 |
| Out-of-Distribution (OOD) | 分布外 | 与训练分布存在差异的样本或测试环境。 |
| Distribution Shift | 分布偏移 | 训练、验证或部署阶段的数据分布发生变化。 |
| Domain Shift | 领域偏移 | 数据来源或环境变化导致的数据分布差异，如白天到夜间。 |
| Generalization | 泛化 | 模型在未见过的数据或条件下保持性能的能力。 |
| Data Leakage | 数据泄漏 | 训练或调参过程不当使用了原本不可用的测试信息等，导致评测偏乐观。 |
| Data Preprocessing | 数据预处理 | 清洗、标准化、编码等训练前处理。 |
| Data Augmentation | 数据增强 | 通过变换或合成样本增加训练多样性。 |
| Cross-Validation (CV) | 交叉验证 | 使用多个划分轮流训练与评估，以减轻单次划分的偶然性。 |
| K-fold Cross-Validation | K 折交叉验证 | 将数据分为 K 份，轮流用其中一份验证、其余部分训练。 |
| Class Imbalance | 类别不平衡 | 各类别的样本数差异较大。 |
| Sampling | 采样 | 按某种规则选取样本或构建数据批次。 |
| Data Scarcity | 数据稀缺 | 可用于训练或评估的数据量不足。 |
| Synthetic Data | 合成数据 | 通过模拟器、生成模型或规则构造的数据。 |

## 4. 模型、训练与优化

| 英文术语 | 常见中文 | 核心含义 / 阅读提示 |
|---|---|---|
| Model | 模型 | 从输入映射到输出的可学习或规则化系统。 |
| Framework | 框架 | 组织多个方法、组件与流程的整体设计。 |
| Pipeline | 处理流程 | 数据进入系统后依次经历的处理步骤。 |
| Architecture | 模型架构 | 网络层、模块及连接关系的结构设计。 |
| Backbone | 主干网络 | 承担主要特征提取工作的基础网络。 |
| Module / Component | 模块 / 组件 | 系统或模型中承担某一功能的部分。 |
| Encoder / Decoder | 编码器 / 解码器 | 将输入映射为表征 / 将表征转换为所需输出的结构。 |
| Embedding | 嵌入表示 | 把离散对象或输入映射到向量空间得到的表示。 |
| Representation | 表征 | 模型用于刻画输入信息的内部形式。 |
| Latent Space | 潜在空间 | 模型学习到的隐变量或抽象表示所在的空间。 |
| Parameter | 模型参数 | 训练过程中被学习或估计的量，如神经网络权重。 |
| Hyperparameter | 超参数 | 训练前或训练过程中由实验者设定/搜索的配置，如学习率。 |
| Loss Function | 损失函数 | 定量衡量预测与目标之间的偏差，是优化过程中使用的目标组成部分。 |
| Objective Function | 目标函数 | 需要最大化或最小化的整体数学表达式；可包括损失、正则项等。 |
| Optimization / Optimizer | 优化 / 优化器 | 寻找更优参数的过程 / 执行参数更新的算法。 |
| Learning Rate (LR) | 学习率 | 控制单次参数更新步幅的超参数。 |
| Regularization | 正则化 | 限制模型复杂度或参数行为，以帮助优化或改善泛化。 |
| Batch / Mini-batch | 批次 / 小批次 | 一次参数更新中使用的一组样本。 |
| Batch Size | 批大小 | 一个批次包含的样本数。 |
| Epoch | 训练轮次 | 按通常定义，训练数据被完整遍历一次。 |
| Iteration / Step | 迭代 / 更新步 | 通常指一次参数更新；具体含义取决于实现。 |
| Checkpoint | 检查点 | 保存的模型权重、优化器状态等训练状态。 |
| Pre-training / Pretrained | 预训练 / 预训练的 | 先在一个数据或任务上学习，再服务于后续任务。 |
| Fine-tuning | 微调 | 在预训练模型基础上继续调整部分或全部参数。 |
| Transfer Learning | 迁移学习 | 将源任务或源域得到的知识用于目标任务或目标域。 |
| Zero-shot / Few-shot | 零样本 / 少样本 | 在目标任务没有或只有少量示例/标注的设定下进行预测或适配；具体定义因论文而异。 |
| End-to-end | 端到端 | 将输入到目标输出的过程联合训练，而非主要依赖分阶段独立优化。 |
| Inference | 推理 | 使用已训练模型对输入产生预测或生成输出。 |
| Convergence | 收敛 | 训练目标、参数或迭代序列趋于稳定；并不自动意味着得到全局最优。 |
| Overfitting / Underfitting | 过拟合 / 欠拟合 | 过于贴合训练数据而泛化差 / 连训练规律也学得不足。 |

## 5. 评价指标与结果分析

| 英文术语 | 常见中文 | 核心含义 / 阅读提示 |
|---|---|---|
| Metric | 评价指标 | 衡量结果质量或系统性能的数值标准。 |
| Accuracy | 准确率 | 分类任务中预测正确的样本比例；类别不平衡时可能误导。 |
| Precision | 精确率 / 查准率 | 预测为正的样本中真正为正的比例：TP / (TP + FP)。 |
| Recall | 召回率 / 查全率 | 实际为正的样本中被成功找出的比例：TP / (TP + FN)。 |
| F1-score | F1 分数 | Precision 和 Recall 的调和平均：2PR / (P + R)。 |
| AUC / ROC-AUC | 曲线下面积 / ROC 曲线下面积 | 常用于衡量二分类模型跨阈值的区分能力；需看具体是哪条曲线。 |
| Confusion Matrix | 混淆矩阵 | 汇总真实类别与预测类别的对应数量。 |
| MAE | 平均绝对误差 | 预测值与真实值的绝对差的平均，越小越好。 |
| MSE | 均方误差 | 预测误差平方的平均，越小越好，对较大误差更敏感。 |
| RMSE | 均方根误差 | MSE 的平方根，与目标变量单位一致。 |
| R² / R-squared | 决定系数 | 衡量回归拟合相对基准预测的表现；可为负数。 |
| Latency | 延迟 | 完成一次请求、推理或操作所需的时间。 |
| Throughput | 吞吐量 | 单位时间能处理的样本、请求或任务数量。 |
| FLOPs | 浮点运算次数 | 近似衡量某次计算的算术工作量；注意和 FLOPS（每秒浮点运算数）区分。 |
| Parameter Count / Params | 参数量 | 模型包含的参数数目；与 FLOPs、运行时间不是一回事。 |
| Memory Footprint | 内存占用 | 模型运行或训练时所需的内存/显存空间。 |
| Computational Cost | 计算成本 | 算力、时间、能源或资金消耗，论文应指明具体计量方式。 |
| Efficiency | 效率 | 在计算、时间、能耗、样本数量等成本约束下的表现。 |
| Robustness | 鲁棒性 | 面对噪声、扰动或条件变化时维持合理表现的能力。 |
| Stability | 稳定性 | 对随机种子、训练过程或输入变化等保持结果一致的程度。 |
| Scalability | 可扩展性 | 随样本量、模型规模或用户数量增加而维持合理性能与成本的能力。 |
| Variance / Standard Deviation (SD) | 方差 / 标准差 | 描述多次运行结果的离散程度；SD 是方差的平方根。 |
| Confidence Interval (CI) | 置信区间 | 依据数据构造、在重复抽样下具有指定覆盖率的区间，需说明估计方法。 |
| Error Bar | 误差棒 | 图中表示结果不确定性或离散性的线段；可能是 SD、SE、CI 等，必须查图注。 |
| Statistical Significance | 统计显著性 | 统计检验下结果与原假设不相容的程度达到既定门槛，不等于实际作用很大。 |
| p-value | p 值 | 在原假设和检验模型成立时，观察到至少同样极端结果的概率；不是“原假设为真的概率”。 |
| Effect Size | 效应量 | 差异或关系的实际大小，补充显著性检验。 |
| Random Seed | 随机种子 | 控制伪随机过程的初始状态；固定种子不保证跨平台完全可复现。 |
| Repeated Runs | 重复运行 | 在不同种子等条件下重复实验以报告波动。 |

**数值比较特别注意：**若 Accuracy 从 90% 提升到 93%，是**提高 3 个百分点**（absolute percentage-point gain），相对提升为 **(93−90)/90≈3.33%**。两者不可混写。

## 6. 论证、结论与学术表达

| 英文术语 | 常见中文 | 核心含义 / 阅读提示 |
|---|---|---|
| Empirical | 实证的 | 基于观察、测量或实验结果。 |
| Theoretical | 理论的 | 基于形式化分析、数学建模或理论推导。 |
| Derive / Derivation | 推导 / 推导过程 | 从已知条件推演出公式或结论。 |
| Prove / Proof | 证明 / 证明 | 用严格论证建立命题在给定前提下成立。 |
| Validate / Validation | 验证有效性 / 验证 | 使用数据、实验或其他证据支持方法的适用性或结果。 |
| Verify / Verification | 核验 / 验证正确性 | 检查实现、计算或结论是否符合规定与预期。 |
| Demonstrate | 证明性展示 / 展示 | 提供实验或例子支持某个论点；不必然是数学严格证明。 |
| Indicate / Suggest | 表明 / 暗示 | **Suggest** 通常比 **demonstrate** 更审慎，表示证据支持某种解释而非确定因果。 |
| Consistent | 一致的 / 稳定一致的 | 与某趋势或已有研究相吻合；需看具体比较对象。 |
| Significant | 显著的 | 可能指幅度明显，也可能指**统计显著**；二者不能自动等同。 |
| Marginal / Modest | 微小的 / 有限的 | 通常表示提升幅度不大，应参考具体数值。 |
| Substantial | 较大的 / 实质性的 | 表示幅度有意义，但仍需要定量数据支撑。 |
| Limitation | 局限性 | 方法、数据或结论的适用边界与不足。 |
| Threats to Validity | 有效性威胁 | 影响研究结论可信度的潜在问题，如混杂因素、泄漏或样本偏差。 |
| Reproducibility | 可复现性 | 能否按提供的方法、数据和计算环境得到一致结果；部分学科对术语界定不同。 |
| Replicability | 可重复验证性 | 通常强调由其他研究者独立重复研究并获得相容结果；与 reproducibility 的使用存在领域差异。 |
| Open-source | 开源 | 代码或其他材料以允许使用、修改或分发的许可证公开；仅公开下载地址不必然等于开源。 |
| Case Study | 案例研究 | 对一个或多个特定案例开展深入分析。 |
| Qualitative / Quantitative | 定性 / 定量 | 主要通过性质、现象与解释分析 / 通过数值和统计分析。 |

## 7. 投稿与同行评审

| 英文术语 | 常见中文 | 核心含义 / 阅读提示 |
|---|---|---|
| Venue | 发表场所 | 论文投递或发表的会议、期刊等。 |
| Conference / Journal | 会议 / 期刊 | 两种常见学术发表形式，不同学科重视程度不同。 |
| Submission | 投稿 | 将稿件提交至会议或期刊。 |
| Preprint | 预印本 | 正式同行评审或发表前公开的论文版本；不代表已经通过评审。 |
| Peer Review | 同行评审 | 由领域研究者评估论文的质量、创新性与可信度。 |
| Reviewer | 审稿人 | 对投稿进行评价并给出修改建议的研究者。 |
| Rebuttal / Author Response | 作者回复 / 申辩 | 针对审稿意见澄清误解、回答问题和补充证据。 |
| Revision | 修订 | 根据反馈修改论文内容。 |
| Acceptance / Rejection | 接收 / 拒稿 | 投稿最终是否被接受发表。 |
| Camera-ready | 终稿 | 已录用、用于正式出版的最终排版稿。 |
| Artifact / Code Release | 研究工件 / 代码发布 | 与论文有关的代码、模型、数据、脚本或运行说明。 |

## 8. 高频易混概念

| 易混组合 | 关键区别 |
|---|---|
| **Benchmark vs. Dataset** | Benchmark 是评测基准，通常还包含任务、指标和规则；Dataset 只是数据。日常语境下 Benchmark 有时被宽泛用来指数据集。 |
| **Benchmark vs. Baseline** | 前者回答“按什么测试”，后者回答“和谁比较”。 |
| **Baseline vs. SOTA** | Baseline 是对照方法；SOTA 是指定评测条件下的领先水平。强 baseline 也可能是 SOTA 方法。 |
| **Loss vs. Metric** | Loss 用于优化训练，Metric 用于评价；二者可以相同，也可以不同。 |
| **Parameter vs. Hyperparameter** | Parameter 通常由训练学习；Hyperparameter 通常由研究者或搜索过程设定。 |
| **Validation Set vs. Test Set** | 验证集用于模型选择，测试集用于最终独立评估。 |
| **Epoch vs. Iteration** | Epoch 是对数据集的一轮遍历；Iteration 常指一次参数更新。若 N 个训练样本、batch size 为 B，单轮更新通常约为 ⌈N/B⌉ 次，具体取决于丢弃尾批、梯度累积等设置。 |
| **Ablation vs. Baseline Comparison** | 消融回答“本文哪些部分产生作用”；基线对比回答“本文整体与已有方法相比如何”。 |
| **Precision vs. Recall** | Precision 关注预测出的正例有多准；Recall 关注真实正例找回多少。 |
| **Robustness vs. Generalization** | 前者侧重扰动、噪声或特定变化下的稳定表现；后者侧重对未见数据的表现。两者可能重叠。 |
| **Statistical Significance vs. Practical Significance** | 统计显著不代表效果大或值得部署；应同时看效应量与成本。 |
| **Reproducibility vs. Replicability** | 不同学术组织定义不完全一致；阅读时优先采用原论文或投稿规范的定义。 |

## 9. 读论文时的五个检查问题

1. **研究问题**：论文解决的具体问题是什么？主要 **contribution** 是什么？
2. **对比对象**：使用了哪些 **benchmarks** 和 **baselines**？是否包含有竞争力的对照方法？
3. **实验公平性**：数据划分、训练预算、调参方式、**evaluation protocol** 是否一致？
4. **证据充分性**：是否报告 **ablation study**、多次运行波动、合适的 **metrics** 和局限性？
5. **结论适用范围**：宣称 **SOTA** 或 **significant improvement** 时，是否限定任务、指标与条件，并提供足够证据？

### 快速记忆

- **Benchmark**：按什么测试？
- **Baseline**：和谁比较？
- **Metric**：用什么指标衡量？
- **Ablation**：哪个组件真正有用？
- **SOTA**：在特定评测设置下，当前最领先的结果是什么？
- **Generalization**：换成没见过的数据还能表现好吗？
- **Reproducibility**：别人能否根据提供的信息得到相容的结果？
